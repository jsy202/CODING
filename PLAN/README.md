# 코딩 테스트 복습 자료 운영 규칙

이 폴더의 목표는 정답을 단순히 보관하는 것이 아니라, 나중에 문제와 풀이를 빠르게 찾아 복습할 수 있게 정리하는 것입니다.

Codex가 자동으로 따라야 하는 상세 문서 추출 지침은 저장소 루트의 [`AGENTS.md`](../AGENTS.md)에 있습니다. 현재 작업 폴더와 관계없이 Word 원본과 CODING 저장소의 절대 경로를 사용하도록 정의되어 있습니다.

## 작업 요청 규칙

사용자가 **`확인`**이라고 말하면 아래 작업을 질문 없이 끝까지 수행합니다.

1. `C:\Users\oie22\OneDrive\Desktop\코테 정답.docx`를 다시 확인합니다.
2. 기존 파일과 비교해 새로 추가된 정답을 찾습니다.
3. 문서의 Day 구분에 맞는 `PLAN/DAY숫자` 폴더에 새 정답을 추가합니다.
4. 해당 Day의 `README.md` 문제 목록을 갱신합니다.
5. 원문과 저장된 코드가 정확히 일치하는지 검증합니다.
6. 변경된 정답 파일과 README만 커밋합니다.
7. 원격 `main`의 최신 변경을 안전하게 반영한 뒤 GitHub에 푸시합니다.
8. 마지막으로 로컬 `main`과 `origin/main`이 동기화됐는지 확인합니다.

## 가장 중요한 원칙

- 정답 코드의 내용, 로직, 표현, 주석, 공백, 빈 줄을 임의로 수정하지 않습니다.
- 오타나 오류가 보여도 정답 파일에서는 고치지 않습니다.
- 가독성은 코드 수정이 아니라 폴더 구조, 파일명, 순서, README 목차와 설명으로 개선합니다.
- Word 원본 파일은 읽기 전용으로 취급하며 수정하지 않습니다.
- 기존 정답을 덮어쓰거나 삭제하지 않습니다.
- 문제명을 확실히 알 수 있을 때만 이름을 붙입니다. 번호나 플랫폼이 불확실하면 추측하지 않고 `-`로 표시합니다.
- 저장소에 사용자의 다른 변경 사항이 있으면 함께 커밋하지 않습니다.

## 파일 정리 형식

- Day 폴더: `PLAN/DAY1`, `PLAN/DAY2`, ...
- 정답 파일: `문서순서_문제명.cpp`
- 예시: `08_자동차_테스트.cpp`
- 각 Day의 `README.md`에는 문서 순서, 플랫폼, 문제 번호, 문제명, 정답 파일 링크를 표로 작성합니다.
- 학습 메모가 원문 코드의 주석에 포함되어 있으면 주석까지 그대로 보존합니다.

## 완료 조건

다음 조건을 모두 만족해야 작업이 끝난 것입니다.

- 새 정답이 빠짐없이 추가됨
- 모든 정답 코드가 Word 원문과 문자 단위로 일치함
- README에서 각 정답 파일을 바로 열 수 있음
- 커밋이 생성됨
- GitHub `main`에 푸시됨
- 작업 트리가 깨끗하고 `main`과 `origin/main`이 동기화됨
